# Access gateway

Задание 07 направления «База знаний и агент вопросов и ответов». Проект создаёт
единую точку проверки доступа поверх любой реализации `Retriever`.

## Подготовка

Выполняйте команды из каталога `intern-tasks/07-access-gateway`:

```bash
uv sync --python 3.11
```

Сеть, внешние серверы и секреты для работы не нужны.

## Как работает шлюз

1. Внешний код передаёт `Subject` и текст вопроса в `AuthorizedRetriever`.
2. Шлюз сам создаёт `RetrievalQuery`, включая пользователя, рабочую область и группы.
3. Внутренняя служба возвращает найденные фрагменты.
4. `GroupAccessPolicy` повторно проверяет каждый фрагмент.
5. Разрешённые фрагменты остаются в результате, запрещённые удаляются.
6. Для каждого отказа создаётся `SecurityEvent` без текста закрытого документа.
7. В `RetrievalResult.policy_version` записывается применённая версия правил.

Даже если внутренняя служба ошиблась и вернула закрытый документ, шлюз не отдаёт
его вызывающему коду.

## Правила групп

Правило по умолчанию запрещает доступ. Известны только такие назначения:

| Группа пользователя | Доступные группы документов |
| --- | --- |
| `all-employees` | `all-employees` |
| `engineering` | `all-employees`, `engineering` |

Неизвестная группа не выдаёт никаких прав. Пустой пользователь, отсутствие групп,
другая рабочая область и пустая группа документа также приводят к отказу.

## Аудит

`JsonlAuditSink` использует `structlog` и пишет JSONL. Событие содержит пользователя,
рабочие области, `source_id`, `revision_id`, `chunk_id`, требуемую группу, причину
отказа и версию правил. Поле с текстом фрагмента в контракте события отсутствует.

Для проверок без файлов доступен программируемый `InMemoryAuditSink`.

## Демонстрация с неисправной службой

```bash
uv run python -m access_gateway
```

`LeakyRetriever` намеренно возвращает инженерный фрагмент обычному сотруднику.
Итоговый список `chunks` будет пуст, а событие появится в
`build/security-events.jsonl`.

Используется только синтетический файл `data/fixtures/leaked-chunk.json`.

## Стандартные проверки

```bash
uv run ruff check .
uv run pytest -q -m 'not integration and not llm'
uv run python -m compileall -q src tests
```

Модульные тесты работают без сети и внешних служб. Они проверяют доступ обычного
сотрудника и инженера, изоляцию рабочих областей, защиту от `LeakyRetriever`,
запрет при пустом пользователе, пустых или неизвестных группах, формирование
запроса самим шлюзом и версию политики. Отдельная проверка читает JSONL-событие и
подтверждает, что в нём есть идентификаторы и причина, но нет закрытого текста.
