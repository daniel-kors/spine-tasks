# Q&A evaluator

Задание 09 направления «База знаний и агент вопросов и ответов». Одна команда
проверяет 30 синтетических сценариев, создаёт JSON и Markdown отчёты и возвращает
код завершения по порогам готовности.

## Подготовка

Выполняйте команды из каталога `intern-tasks/09-qa-eval`:

```bash
uv sync --python 3.11
```

Сеть, языковая модель и API-ключ не нужны.

Файл `data/evals/v1.jsonl` скопирован без изменения из
`synthetic-data/01-knowledge-base-and-qa/evals/v1.jsonl`. Он содержит 30 примеров.
Весь файл проверяется до первого обращения к оцениваемой системе: пустые и
повторяющиеся `case_id`, неизвестные поля, неверные типы, смешанные версии схемы и
ошибочные регулярные выражения отклоняются сразу.

## Запуск хорошей заглушки

```bash
uv run python -m qa_eval run data/evals/v1.jsonl
```

Команда создаёт:

- `build/report.json` — полный машинный отчёт;
- `build/report.md` — сводка и таблица отдельных провалов.

Воспроизводимые ответы заглушки находятся в
`data/fixtures/good-results.jsonl`. Система получает только рабочую область, группы
и вопрос. Ожидаемые результаты остаются внутри evaluator.

## Проверка обнаружения утечки

```bash
uv run python -m qa_eval run data/evals/v1.jsonl --adapter leaky-fake
```

`LeakyQaSystem` добавляет закрытый источник `engineering-only`. Отчёты всё равно
создаются, но `ready` становится `false`, а команда завершается с кодом 1.

## Что проверяется

Для каждого примера evaluator независимо собирает источники контекста и ссылок и
проверяет:

- наличие всех ожидаемых источников без учёта их положения;
- отсутствие запрещённых источников и в контексте, и в ссылках;
- точное совпадение `chunk_id`, `revision_id` и `locator` ссылки с контекстом;
- ожидаемый статус `answered` или `abstained`;
- ожидаемые редакции, если они указаны;
- обязательные факты после нормализации регистра и пробелов;
- регулярные выражения из `required_patterns`.

Длительность измеряется отдельно и не влияет на правильность. Ошибка одного
вызова превращается в `SYSTEM_ERROR`, после чего остальные примеры продолжают
выполняться.

## Пороги готовности

Результат получает `ready=true`, только если одновременно выполнены условия:

| Показатель | Порог |
| --- | ---: |
| Запрещённые источники | 0 |
| Действительные ссылки | 100% |
| Ожидаемые источники | не менее 85% подходящих примеров |
| Правильный статус | не менее 80% всех примеров |

Обязательные факты и шаблоны выводятся отдельным показателем и отдельными кодами
провалов. Их длительность и положение фрагментов не меняют перечисленные пороги.

## Коды завершения

- `0` — все пороги готовности пройдены;
- `1` — создан отчёт, но нарушен хотя бы один порог;
- `2` — входные данные или параметры команды некорректны.

## Состав пакета

- `dataset.py` — полная проверка JSONL;
- `checks.py` — маленькие чистые проверки одного результата;
- `system.py` — интерфейс системы и файловые заглушки;
- `runner.py` — выполнение всех примеров и расчёт порогов;
- `reports.py` — JSON и Markdown отчёты;
- `cli.py` — команда Typer и таблица Rich.

## Стандартные проверки

```bash
uv run ruff check .
uv run pytest -q -m 'not integration and not llm'
uv run python -m compileall -q src tests
```

Модульные тесты отдельно проверяют чистые функции, хороший вручную собранный
результат, выдуманную ссылку, одну утечку среди правильных результатов и
отсутствующий ожидаемый источник независимо от положения остальных фрагментов.
Также проверяются пустой и повторяющийся `case_id`, воспроизводимость файловой
заглушки и сквозные коды завершения `0` и `1` через `typer.testing.CliRunner`.
