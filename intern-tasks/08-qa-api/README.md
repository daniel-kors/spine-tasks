# Q&A API

Задание 08 направления «База знаний и агент вопросов и ответов». Проект предоставляет
HTTP-интерфейс поверх получения контекста, составления черновика и независимой
проверки ответа.

## Подготовка

Выполняйте команды из каталога `intern-tasks/08-qa-api`:

```bash
uv sync --python 3.11
```

По умолчанию работает полностью локальный режим `QA_MODE=fake`: сеть, языковая
модель и API-ключ не нужны.

## Запуск

```bash
uv run uvicorn qa_api.main:app --reload --port 8080
```

Проверка состояния:

```bash
curl -s http://127.0.0.1:8080/health/live
curl -s http://127.0.0.1:8080/health/ready
```

В fake-режиме `/health/ready` возвращает готовность без языковой модели.

## Три обязательных сценария

Подтверждённый ответ:

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/ask \
  -H 'Content-Type: application/json' \
  -d '{"workspace_id":"alpha","user_id":"u-1","scopes":["all-employees"],"question":"Какой размер суточных?","request_id":"demo-001"}'
```

Отказ из-за отсутствия сведений:

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/ask \
  -H 'Content-Type: application/json' \
  -d '{"workspace_id":"alpha","user_id":"u-1","scopes":["all-employees"],"question":"Какой пароль от сервера?","request_id":"demo-002"}'
```

Запрос из другой рабочей области не раскрывает документ `alpha`:

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/ask \
  -H 'Content-Type: application/json' \
  -d '{"workspace_id":"beta","user_id":"u-2","scopes":["all-employees"],"question":"Какой размер суточных?","request_id":"demo-003"}'
```

Каждый успешный HTTP-вызов возвращает `status`, `answer`, `citations`,
`index_version`, `policy_version`, `trace_id`, `as_of` и `reasons`.

## Устройство программы

- `service.py` — независимая от FastAPI служба `AskQuestion`;
- `ports.py` — интерфейсы шлюза, составителя, валидатора и часов;
- `routes.py` — только HTTP-маршруты;
- `application.py` — сборка зависимостей и безопасные обработчики ошибок;
- `main.py` — только создание ASGI-приложения;
- `fakes.py` — локальные реализации для воспроизводимого запуска;
- `models.py` — строгие Pydantic-контракты с `extra="forbid"`.

## Защита от повторов

Первый вызов с `request_id` выполняет работу и сохраняет `AskResponse` в памяти.
Повтор с тем же телом получает логически тот же объект, включая `trace_id` и
`as_of`. Одновременные повторы ожидают одну общую операцию. Использование того же
`request_id` для другого запроса возвращает `REQUEST_ID_CONFLICT`.

Хранилище находится в памяти процесса и очищается после перезапуска сервера.

## Ограничения и ошибки

- вопрос содержит от 1 до 2000 символов и не может состоять из пробелов;
- запрос содержит от 1 до 20 групп доступа;
- неизвестные поля отклоняются с HTTP 422;
- тайм-аут составителя возвращает HTTP 503, `COMPOSER_TIMEOUT` и `retryable=true`;
- ошибки имеют единый безопасный вид: `code`, `message`, `trace_id`, `retryable`;
- стек вызовов и внутренние инструкции модели в ответ не включаются.

Идентификатор `trace_id` записывается в события `structlog` при начале и завершении
запроса, а также при управляемой ошибке.

## Синтетические данные

Fake-режим читает только `data/fixtures/fake-context.json`. В нём находятся
открытый документ о командировках и закрытый инженерный пример.

## Стандартные проверки

```bash
uv run ruff check .
uv run pytest -q -m 'not integration and not llm'
uv run python -m compileall -q src tests
```

HTTP-тесты используют `httpx.ASGITransport`, подставляют подготовленную службу
через `app.dependency_overrides` и не открывают сетевой порт. Они проверяют точный
указатель ссылки, неизвестное поле, пустой вопрос, повтор `request_id`, изоляцию
рабочих областей, управляемый тайм-аут, совпадение `trace_id` в ответе и журнале,
а также готовность fake-режима без языковой модели.
