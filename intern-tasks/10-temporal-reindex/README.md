# Temporal reindex

Задание 10 направления «База знаний и агент вопросов и ответов». Temporal управляет
длительной переиндексацией, повторными попытками, состоянием и отменой. Разбор
документов и изменение проекции остаются в обычной прикладной службе.

## Подготовка

Выполняйте команды из каталога `intern-tasks/10-temporal-reindex`:

```bash
uv sync --python 3.11
```

Temporal SDK и его точная версия сохранены в `uv.lock`.

## Разделение ролей

- `workflow.py` — только детерминированный порядок действий;
- `activities.py` — граница Temporal над прикладной службой;
- `service.py` — обычная идемпотентная служба проекции;
- `worker.py` — подключение исполнителя и регистрация workflow с activities;
- `starter.py` — клиент, запускающий новый процесс;
- `models.py` — Pydantic-контракты входа, состояния, результата и операций.

Workflow не читает файлы, сеть, случайные числа или системное время. Он получает
готовые пути во входном контракте и вызывает именованные activities.

## Последовательность переиндексации

1. `validate_manifests` проверяет входные описания.
2. `create_projection` создаёт неактивную версию.
3. Пути разбиваются на группы по 10.
4. `index_batch` индексирует каждую группу.
5. `verify_projection` убеждается, что обработано ожидаемое число элементов.
6. `activate_projection` вызывается только после полной успешной проверки.
7. При исчерпании попыток вызывается `mark_failed`.

Для 25 путей получаются группы размером 10, 10 и 5.

## Повторные попытки и защита от дублей

`index_batch` получает ключ вида:

```text
workflow_id/index-batch-N/N
```

Прикладная служба хранит результат по этому ключу внутри конкретных
`workspace_id` и `projection_id`. Повтор activity возвращает прежнее число и не
индексирует группу второй раз.

Для `index_batch` настроены три попытки с интервалами Temporal 1, 2 и максимум 5
секунд. Ошибка `ManifestValidationError` помечена как не допускающая повторной
попытки.

## Наблюдение и отмена

Запрос `progress` возвращает:

- состояние процесса;
- число обработанных элементов;
- общее число элементов;
- признак запроса отмены.

Сигнал `request_cancel` устанавливает признак отмены. Workflow проверяет его между
группами и перед активацией. Отменённая или неполная проекция не активируется.

## Необязательный локальный запуск

В первом терминале запустите локальный сервер Temporal:

```bash
temporal server start-dev
```

Во втором терминале запустите worker:

```bash
uv run python -m temporal_reindex.worker
```

В третьем терминале запустите пример с 25 описаниями:

```bash
uv run python -m temporal_reindex.starter --workspace alpha --projection demo-v1 --manifest-count 25
```

История процесса доступна в локальном веб-интерфейсе Temporal, который выводит
команда `temporal server start-dev`. Адрес и очередь можно изменить через
`.env.example`.

Локальный сервер является демонстрацией и не нужен для автоматических проверок.

## Проверки без Docker

На Linux и macOS связные тесты используют
`WorkflowEnvironment.start_time_skipping()` и временный исполнитель. Ускоренное
время позволяет проверить интервалы повторов без реального ожидания.

На этом Windows-хосте официальный Java test-server Temporal не может создать
внутреннее loopback-соединение. Поэтому тестовый helper по умолчанию запускает на
Windows официальный Temporal dev-server через `WorkflowEnvironment.start_local()`.
Он также работает без Docker. Для принудительной попытки time-skipping режима:

```powershell
$env:TEMPORAL_TEST_MODE = "time-skipping"
```

Связные проверки помечены `integration`, потому что при первом запуске Temporal
SDK может скачать серверный исполняемый файл. Стандартные проверки не требуют
сети:

```bash
uv run ruff check .
uv run pytest -q -m 'not integration and not llm'
uv run python -m compileall -q src tests
```

Связные проверки workflow запускаются отдельно:

```bash
uv run pytest -q -m integration
```

Они проверяют однократную активацию, две временные ошибки третьей группы,
неповторяемую ошибку манифеста, отмену после первой группы и монотонный прогресс.
Модульные проверки отдельно подтверждают разбиение `10/10/5`, идемпотентность
повторной activity и отсутствие прямого ввода-вывода и недетерминированных вызовов
в `workflow.py`.
